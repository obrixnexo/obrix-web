OBRIX NEXO · WEB (tienda + paneles)
====================================

Qué es
------
La web que ven los compradores, las constructoras y el equipo de Obrix.
Son archivos HTML, CSS y JavaScript sin compilar: se abren en el navegador y hablan con la API (obrix-api).

  index.html      la página (carga lo demás)
  config.js       dirección de la API (localhost:8080 en tu laptop; API_EN_LA_NUBE cuando está publicada)
  css/styles.css  el diseño
  js/core.js      utilidades: llamadas a la API, sesión, rutas (#/saldos, #/panel...)
  js/public.js    tienda: inicio, catálogo, ficha, pedido, seguimiento del pedido
  js/auth.js      ingreso, cambio de contraseña y armazón del panel
  js/company.js   panel de la constructora (Admin Empresa y Admin Proyecto)
  js/import.js    carga masiva de saldos desde Excel (plantilla, revisión fila por fila y creación)
  js/dashboard.js tablero de la gerencia (Resumen): recuperado, flujo de saldos, por vencer y ventas
                  por mes, por obra y por material, con detalle al pasar el mouse y tabla
  js/approval.js  aprobación interna (bandeja del aprobador, ficha, historial), avisos (campanita) y
                  configuración de aprobadores en el panel de Obrix
  vendor/         librerías de terceros guardadas aquí (ExcelJS y JSZip, licencia MIT; se cargan solo al usar la carga masiva)
  js/obrix.js     panel de Obrix (revisión de saldos, pedidos y pagos, constructoras, solicitudes)

Cómo abrirla en tu laptop
-------------------------
1. Docker Desktop abierto y la API corriendo en IntelliJ (como siempre).
2. En PowerShell, dentro de esta carpeta:
     npx --yes http-server -p 5500 -c-1
3. Abre en el navegador:  http://localhost:5500

Usuarios de prueba (contraseña Obrix2026!):
  operador@obrixnexo.com          panel de Obrix
  gerencia@constructora-demo.pe   Admin Empresa · aprobador de nivel 1
  almacen@constructora-demo.pe    Admin Proyecto (almacén) · carga los saldos

Direcciones útiles
------------------
  #/              inicio
  #/saldos        catálogo
  #/saldo/OBX-... ficha de un saldo
  #/pedido/TOKEN  seguimiento de un pedido (el enlace que recibe el comprador)
  #/ingresar      ingreso al panel
  #/panel         panel (según el rol)

Aprobación interna de saldos
----------------------------
Borrador → aprobación de la constructora (nivel 1 … N) → revisión de Obrix → tienda.
- Quien carga (almacén) envía el saldo. Los aprobadores de su nivel lo ven en "Aprobaciones" y lo aprueban o rechazan
  (el rechazo exige motivo y vuelve a quien lo cargó; al corregir, reinicia en el nivel 1).
- Nadie aprueba un saldo que cargó o envió él mismo.
- Obrix define cuántos niveles tiene cada constructora y quién aprueba en cada uno:
  panel de Obrix → Constructoras → "Aprobación". No requiere tocar código.
- "Avisos" (la campanita) muestra lo que espera tu aprobación y lo que pasó con tus saldos.

Términos y condiciones
----------------------
Los perfiles de las constructoras los aceptan al ingresar (una vez por versión) y los compradores al pedir.
El texto está en la landing (obrixnexo.com/terminos/); la versión vigente la define la API (TERMS_VERSION).

Carga masiva de saldos (Excel)
------------------------------
Panel de la constructora → Saldos → "Cargar desde Excel".
1. "Descargar plantilla": un .xlsx con las columnas del formulario y listas con las obras activas,
   categorías, unidades y estados.
2. La constructora la llena (hasta 500 saldos por archivo) y la sube.
3. La plataforma revisa cada fila con las mismas reglas del formulario y muestra qué corregir.
   Si un saldo con el mismo nombre ya existe en esa obra, la fila se omite (así no se duplica al volver a subir).
4. "Crear saldos" crea cada fila con la misma API del formulario (la API vuelve a validar todo).
   Quedan en BORRADOR: luego se les agregan fotos y se envían a aprobación de la constructora.
5. "Descargar filas que faltan" baja solo las filas con errores y el motivo, para corregir y volver a subir.
No necesita cambios en el backend.

Publicarla en internet (demo)
-----------------------------
Netlify (proyecto obrix-nexo-demo) está conectado a GitHub (obrixnexo/obrix-web, rama main):
cada cambio que se sube a main se publica solo en 1 o 2 minutos.
Si la API estaba dormida, la web muestra "Encendiendo la demo…" hasta que responda (~1 minuto).
